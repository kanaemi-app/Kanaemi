# 変換の経緯を、変換と同じ道筋で集めて返す

状態：採用

## 背景

辞書は Kanaemi の外で作り、文書の読みを変換して正解と比べる評価で育てる。評価で外れが出ても、なぜその候補が出たのか、なぜ正解がその順位なのか、なぜ正解が出なかったのかは、Kanaemi のコードを読んで推し量るしかなかった。辞書の問題か Kanaemi の問題かを切り分けるたびに、両方の作者の手が要った。

## 決定

engine は、1 回の変換について、候補を集めて並べた経緯を返す。経緯は変換と同じ道筋を通って集め、別の実装で組み立て直さない。経緯には、出した候補の出どころと並びの根拠に加えて、集めたのに絞った候補とその理由、引いた見出しを含める。

## 検討した他の案

- 経緯を、変換とは別の実装で組み立てる：変換を変えたときに経緯だけが古いまま残る。実際と食い違う経緯は、外れの原因を取り違えさせる。
- 出した候補の経緯だけを返す：辞書を育てるときに多い問いは「なぜ正解が出なかったか」で、出した候補からは答えられない。
- 経緯をログに書く：評価のプログラムが、外れごとに読んで分類できない。

## 結果

- 辞書を作る側は、外れを Kanaemi の中を読まずに分類できる。
- 変換の道筋を変えると、経緯も同じ変更で変わる。経緯の形は辞書を作る側が頼るので、形を変えるときは辞書を作る側の評価も合わせて直す。
