# ログには、打ったキーとその結果を、文字を伏せていつも書く

状態：採用

## 背景

不具合のほとんどは、どのキーをどの順に打ち、IME がそれぞれに何を返したかが分からないと追えない。キーごとの記録は、利用者の打った文字をそのまま含むので、開発用のビルドでだけ書いていた。利用者のもとで起きた不具合は、ログを見ても、何かが起きたことしか分からなかった。

## 決定

- ログには、IME に届いたキーやできごとと、IME がそれに返したものを、いつも書く。
- 利用者の打った文字（読み・候補・確定した文字列・文字のキー）は、ログに書く前に伏せる。文字は、ひらがな・カタカナ・漢字・英字・数字といった文字の種類だけを残す。Kanaemi の印、記号、名前のあるキー（Enter など）、文字の数、カーソルの位置は残す。

## 検討した他の案

- キーごとの記録はメモリにだけ持ち、不具合を見つけたときにまとめて書く：IME が不具合と気づけるものしか残らない。利用者が気づいた不具合は、IME には見えないことが多い。
- 文字をそのまま書き、送る前に利用者に確かめてもらう：ログのファイルに打ったものがそのまま残る。ログは長く、利用者が全部を確かめることはできない。
- 文字の数だけを残す：大文字で ABC モードになるなど、文字の種類で振る舞いが変わる不具合を追えない。

## 結果

- ログを送れば、どのキーで何が起きたかを、文字の中身を知らずに追える。
- 文字の中身に依る不具合（特定の語の変換など）は、ログだけでは追えない。利用者に語を聞く。
- ログは打つたびに伸びる。IME が動いているあいだも、大きくなったら古いログとして残し、新しく書き始める。
- キーを処理するところは、ログをディスクに書くのを待たない。書き終わる前に IME が落ちると、最後の数行を失う。
